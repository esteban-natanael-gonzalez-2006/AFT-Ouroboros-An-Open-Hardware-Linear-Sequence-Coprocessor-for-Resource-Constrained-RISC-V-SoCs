21. Qué descubrimiento buscaría

Hay cuatro resultados posibles, y cada uno nos diría algo diferente:

Caso 1

La calidad sigue creciendo con D y los costes también.

→ Ouroboros es principalmente una arquitectura escalable convencional con una buena implementación.

Caso 2

La calidad se satura rápidamente, pero la eficiencia permanece extraordinaria.

→ Tiny/edge architecture.

Caso 3

La calidad continúa creciendo mientras el working set permanece relativamente pequeño gracias a la estructura.

→ Arquitectura especialmente interesante para aceleradores/cache-local.

Caso 4

La calidad mejora mucho cuando aumenta contexto, pero no tanto cuando aumenta D.

→ La principal capacidad de Ouroboros podría estar en la dinámica recurrente, no simplemente en el número de parámetros.

Ese último caso sería particularmente interesante dada la evidencia actual de dependencia del estado.

Sistema 1 tiene paralelismo estructural, pero la CPU monohilo paga aproximadamente \(69.5,ns\) por slot.

El working set es deliberadamente pequeño y está diseñado alrededor de caché.

El entrenamiento puede alcanzar ~16k tok/s cuando el proceso obtiene prácticamente todo el tiempo de CPU, pero el throughput de pared cae cuando la ocupación CPU cae.

La representación aprendida muestra una dependencia fuerte del estado y del corpus, con una enorme brecha entre in-domain y OOD.
